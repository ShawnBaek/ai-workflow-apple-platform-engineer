# apple-platform-ui

UI implementation skill for indie developers building **Apple-platform apps** — iOS, iPadOS, watchOS, macOS.

Turns vague design intent into **SwiftUI / UIKit code** that compiles in Xcode the first time. Every decision (layout, colors, fonts, symbols, navigation) is made for you, grounded in Apple's Human Interface Guidelines. No design background required.

## What it does

- Picks the right navigation container per platform (`NavigationStack` vs `NavigationSplitView` vs Watch).
- Names exact SF Symbols (verified against SF Symbols 5+).
- Splits every screen into a `Screen` (data, side effects) + `Content` (pure pixels) pair so previews are fast and code is testable.
- Injects mock data through a `UseCase` protocol — UI only, no business logic.
- Always emits **three `#Preview` blocks**: Light, Dark, Dynamic Type XXL.
- Enforces semantic colors, semantic fonts, RTL safety, ≥ 44 pt tap targets.
- Disney 12 animation principles distilled to a SwiftUI cheat-sheet.
- **Launch screen** done right — `UILaunchScreen` Info.plist dict for new projects (no logo, no spinner, no text — looks like the first frame), with the rationale and the Light/Dark color-asset setup.
- **Keyboard handling** — `@FocusState` flow, `.scrollDismissesKeyboard`, keyboard toolbar with Done, `safeAreaInset` to pin a Save button above the keyboard, opt-out via `.ignoresSafeArea(.keyboard)`. Plus the UIKit notification pattern for legacy screens.

## What it deliberately doesn't do

- Write business logic, networking, persistence, or auth.
- Design custom icons (use SF Symbols).
- Use custom fonts (use `Font.system(...)`).
- Recommend paid design tools (free tools only: SF Symbols app, Icon Composer, GIMP, Inkscape, Blender).
- Let you rebuild-tweak-rebuild — it reasons through layout in-head before suggesting ⌘R.

## When to use

- "Build me a profile screen for iOS."
- "Make this view work on iPad and Mac too."
- "What's the SwiftUI for a tab-switching settings screen?"
- "Why does my `TextEditor` show a gray background on Mac?"
- "How do I structure state for an editor screen with a focus field?"
- "Set up the launch screen — App Review just rejected mine for having a logo."
- "The keyboard is covering my Save button — how do I pin it above?"
- "How do I set up Next / Next / Go focus flow in a sign-in form?"

## Prerequisites

- **iOS 26 / macOS 26 / watchOS 26 minimum.** This agent assumes current OS APIs throughout — `@Observable`, `ContentUnavailableView`, `.symbolEffect(.bounce)`, `.navigationTransition(.zoom)`, `keyboardLayoutGuide`, `UILaunchScreen`. No legacy fallbacks. Indie devs ship for the OS Apple ships.
- Latest Xcode (matches the deployment target).
- For app icons: Apple's **Icon Composer** (free, ships with Xcode tooling).
