# NotesJournalWebsite — one-page reference site

Sample marketing site **generated by the `app-website` agent** to show what its output looks like in practice. Markets the [`NotesJournal`](../NotesJournal/) example app.

Single page, five sections in canonical order, built entirely with [SwiftUI-For-Web](https://github.com/ShawnBaek/SwiftUI-For-Web). Every spacing decision comes from the Gridlover-style rhythm tokens in [`styles/tokens.css`](styles/tokens.css). Aesthetic anchored on [developer.apple.com/swiftui](https://developer.apple.com/swiftui/) and [airbnb.com](https://www.airbnb.com).

## What this example demonstrates

| Principle (from the agent) | Where to see it |
|---|---|
| SwiftUI-For-Web stack — no plain HTML/JSX | every `sections/*.js` imports from `swiftui-for-web` |
| **Responsive: mobile / tablet / desktop** | [`styles/tokens.css`](styles/tokens.css) — three breakpoint blocks regenerate the full Gridlover scale at each (24px / 27px / 30px baselines) |
| **Mobile-first** | default tokens are mobile; `@media (min-width: 768px)` upgrades to tablet; `@media (min-width: 1024px)` to desktop |
| Stacks collapse on narrow viewports | `HStack({ wrap: true })` everywhere a row would overflow |
| Outer padding lives in `.section` class | not inline — so it can change per breakpoint without touching JS |
| iPhone screenshot width is responsive | `.iphone-frame { width: var(--iphone-w); }` — min(85vw, 280px) mobile, 280px tablet, 320px desktop |
| Parallax intensity reduces on mobile | smaller `@keyframes` distance (20vh vs 40vh) below 1024px |
| Animations respect `prefers-reduced-motion` | `.reveal` and `.parallax-figure` disabled when user requests reduced motion |
| Gridlover vertical rhythm at every viewport | each breakpoint's spacing scale is a clean multiple of its baseline |
| Tokens drive type | helper classes `.display`, `.h1`, `.h2`, `.h3`, `.lead`, `.body` map to the responsive `--fs-*` and `--lh-*` vars |
| One typeface | system font stack only — no web font load |
| One weight per role | display = 700, headings = 600, body = 400 |
| Body capped at 60–80 char measure | `--measure: 38em` on `.lead` and `.body` |
| Semantic colors with dark mode | `--color-label` / `--color-secondary-label` redefine inside `@media (prefers-color-scheme: dark)` |
| Reveal-on-scroll, declarative | `.reveal` class + `animation-timeline: view()` in tokens.css |
| Parallax in exactly one section | only `.parallax-figure` in [`ParallaxShowcase.js`](sections/ParallaxShowcase.js) |
| No nav bar, no hamburger | one-pager principle — anchor links optional, no nav |
| No third-party scripts | share buttons use native share-intent URLs; copy-link uses `navigator.clipboard` |
| Lazy-load below the fold | `.loading('lazy')` on every image past the hero |
| Performance budget honored | tiny `index.html` shell; SwiftUI-For-Web is the only JS dep |

## How to run

### Quick run (anything works)

```bash
cd examples/NotesJournalWebsite
python3 -m http.server 8000
# open http://localhost:8000
```

**Do not open `index.html` via `file://`** — Chrome blocks ES modules from local files. You'll get a blank page. Always serve over HTTP.

No `npm install` is required: the [importmap in `index.html`](index.html) resolves `swiftui-for-web` to the GitHub repo via jsDelivr's CDN.

### Recommended: no-cache dev server

Python's `http.server` doesn't send `Cache-Control` headers, which means **browser-cached modules will persist across your edits** — you'll see stale code and wonder why. Use this snippet instead:

```bash
# tools/nocache-server.py
cat > /tmp/nocache.py << 'EOF'
import http.server, socketserver, sys
PORT = int(sys.argv[1]) if len(sys.argv) > 1 else 8000
class H(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control', 'no-store, no-cache, must-revalidate, max-age=0')
        self.send_header('Pragma', 'no-cache')
        super().end_headers()
with socketserver.TCPServer(("", PORT), H) as httpd:
    httpd.serve_forever()
EOF

python3 /tmp/nocache.py 8000
```

Verify with `curl -sI http://localhost:8000/main.js | grep -i cache` — should show `Cache-Control: no-store`.

### If your edit doesn't show up

ES modules cache aggressively even with no-cache headers (Chrome's module cache survives page reloads). Three escalating fixes:

1. **Hard refresh** the page: `⌘+Shift+R` (Mac) / `Ctrl+Shift+R` (Win).
2. **Close the tab and open it fresh.** Module cache doesn't survive tab close.
3. **Bump the cache-buster on `<script src="./main.js?v=N">`** in [`index.html`](index.html) — `index.html` is in the doc cache, but the query string forces a fresh module graph.

### Verified in a real browser

This example was loaded in Chrome via the `Claude_in_Chrome` MCP and verified visually + functionally (every `<img>.naturalWidth > 0`) at every change.

### Lean-hard mode — ~75% SwiftUI-For-Web modifiers, ~25% CSS

After auditing how much of the example was actually using SwiftUI-For-Web's API vs leaning on CSS escape hatches, the example was rewritten to use the real chainable modifiers everywhere they exist:

| Real modifier | Count across 5 sections | Replaces |
|---|---|---|
| `.font(Font.system(size, weight))` | 7 | `cls('display')` / `cls('h1')` / etc. |
| `.foregroundColor(cssColor(varName))` | 9 | `cls('color-secondary')` / CSS color classes |
| `.padding({ vertical, horizontal })` | 6 | `cls('section')` |
| `.frame({ width, height })` | 4 | `cls('iphone-frame')` |
| `.shadow({ y, radius, color })` | 2 | CSS `box-shadow` |
| `.onTapGesture(handler)` | 7 | `openOnTap` / `copyOnTap` helpers (now obsolete) |

Module structure:
- [`sections/theme.js`](sections/theme.js) — `cssColor()` wraps a CSS-var in a Color-shaped object (so dark mode still cascades); `responsive(mobile, tablet, desktop)` returns viewport-aware values; `SPACING` and `TYPE` constants.
- [`sections/typography.js`](sections/typography.js) — `display()`, `h1()`, `h2()`, `h3()`, `lead()`, `body()`, `caption()` factory functions that return `Text(...).font(Font.system(...))` with the right size/weight/line-height/letter-spacing per role.
- [`sections/helpers.js`](sections/helpers.js) — only 20 lines now. Just `attrs` (for `alt`/`aria-*`/`loading`/`role`) and `cls` (for animation/hover class hooks).

[`styles/tokens.css`](styles/tokens.css) shrank from 291 lines to **108 lines** — covers only:
- CSS variables for color tokens (so dark mode follows `prefers-color-scheme`)
- `:hover` states (no `.onHover` modifier exists)
- `animation-timeline: view()` scroll-driven animations (CSS-only feature)
- `.row-wrap` helper (HStack has no `wrap` prop)
- `prefers-reduced-motion` override

That's the honest split: SwiftUI-For-Web does the visual work, CSS does only what the framework genuinely can't.

### Notes for anyone reproducing this

- `import { App } from 'swiftui-for-web'` is a bare specifier — it requires an importmap in `index.html`. Without it: blank page + `Failed to resolve module specifier`.
- **Tempting modifiers that don't exist**: `Link`, `.className()`, `.style()`, `.ariaLabel()`, `.loading()`, `HStack({ wrap: true })`, CSS-variable strings as spacing args. Replacements are in the table above.
- Footer carries a **"Made with SwiftUI-For-Web ↗"** credit linking back to the framework repo — see the last `caption(...)` in [`sections/ShareSection.js`](sections/ShareSection.js). The agent ships this on every generated site.

## Design choices the agent made (and why)

- **No nav bar.** This is a one-pager; the visitor scrolls. Anchor links would add visual noise that fights with the hero. Apple's SwiftUI page does the same.
- **Stepped rhythm per breakpoint, not fluid `clamp()`.** A strict baseline grid only holds at one viewport — fluid scaling breaks it. Three Gridlover scales (mobile 16/24, tablet 18/27, desktop 20/30) keep the rhythm intact at every viewport. The eye perceives "this is the mobile rhythm" cleanly.
- **Display headline scales from ~50px (mobile) → 72px (tablet) → 80px (desktop).** Pulls from the breakpoint-aware `--fs-display`. Generated by [Gridlover](https://www.gridlover.net) at the three bases. Same rhythm theory as [shawnbaek-WPTheme](https://github.com/ShawnBaek/shawnbaek-WPTheme).
- **Outer padding is on `.section`, not inline.** SwiftUI-For-Web inline `.padding({ horizontal: 60 })` would overwrite media queries. Move the responsive bit to CSS, keep the layout in JS.
- **`--space-4` between top-level sections, `--space-5` (240px on desktop) for the parallax break.** Dramatic vertical breathing room reads as confidence; tight stacking reads as a SaaS dashboard.
- **Body text capped at `--measure: 38em`.** Long lines tire the eye after ~75 characters. Even on a 4K display, the lead and body never run wider than this.
- **System font stack, no web font load.** Zero CLS, zero extra HTTP request. The page feels native because it is.
- **Semantic colors via CSS variables.** Light/dark is one media query swap — no per-element overrides.
- **Reveal-on-scroll using `animation-timeline: view()`** (CSS scroll-driven animations). Declarative, framework-free, no IntersectionObserver code. Falls back gracefully on browsers that don't support it (elements just appear without animation).
- **One parallax moment.** Two parallax sections in a row trains the visitor to scroll past your content. One is cinematic; two is loud.
- **Share intents, not SDKs.** AddThis et al. bloat the page and track visitors. Native intent URLs work in every browser, weigh zero bytes.

## What's intentionally missing

- **Binary assets.** The agent-design repo doesn't ship PNGs; see [`assets/README.md`](assets/README.md) for what files to drop in.
- **An email-capture form.** Belongs on a separate page if you want one — not on the conversion-critical one-pager.
- **A cookie banner.** Add one only if you're operating in the EU and using cookies (this template uses zero).
- **Analytics.** Add Plausible / Fathom / a one-line GA snippet to `index.html` if you must — none baked in.
- **A blog or changelog.** Different page. This template is the front door, not the lobby.

## Deploy

The [`app-website`](../../plugins/app-website/README.md) agent's README has the full deploy playbook (GitHub Pages, custom domain, HTTPS). Quick version:

```bash
# Already in this repo's git history; push to a new repo named `<owner>.github.io` or any repo.
git init && git add . && git commit -m "feat(site): initial one-pager"
git remote add origin git@github.com:shawnbaek/notesjournal-website.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Source: Deploy from branch → main → / (root)**. Live in ~1 minute at `https://shawnbaek.github.io/notesjournal-website/`.

For a custom domain like `notesjournal.app`, add a `CNAME` file with that single line and set the DNS A records per the agent's guide.
