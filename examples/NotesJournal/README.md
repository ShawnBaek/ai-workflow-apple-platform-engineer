# NotesJournal — multiplatform example

Sample SwiftUI app **generated by the `apple-platform-ui` agent** to show what its output looks like in practice. Targets **iOS, iPadOS, macOS, and watchOS** from a single shared codebase.

A minimal notes/journal app — list of notes, a tappable row, a full editor, and a watch-friendly compact list. UI only, no business logic, all data injected through a mocked `NotesUseCase`.

## What this example demonstrates

| Principle (from the agent) | Where to see it |
|---|---|
| SF Symbols only — no custom icons | `square.and.pencil`, `note.text`, `doc.text`, `clock` in [NotesListView](Sources/Views/NotesListView.swift), [NoteRowView](Sources/Views/Components/NoteRowView.swift) |
| Semantic colors only — no hex | `.primary`, `.secondary`, `.tertiary`, `.tint`, `.background` everywhere |
| Semantic typography (`Font.system` styles) | `.largeTitle.weight(.semibold)`, `.headline`, `.subheadline`, `.caption`, `.caption2` |
| Three `#Preview` blocks: Light / Dark / XXL | every view file |
| Dynamic Type survives accessibility sizes | `.dynamicTypeSize(.accessibility3)` previews |
| `.leading` / `.trailing` (RTL safe) | no `.left` / `.right` anywhere |
| Mock UseCase injection, UI-only | [NotesUseCase.swift](Sources/UseCases/NotesUseCase.swift) + [MockNotesUseCase.swift](Sources/UseCases/MockNotesUseCase.swift) |
| Platform-specific navigation | `NavigationSplitView` on iOS/iPadOS/macOS, `NavigationStack` on watchOS — see [NotesRootView](Sources/Views/NotesRootView.swift) |
| Empty state via `ContentUnavailableView` | [NotesListView](Sources/Views/NotesListView.swift), [EmptyStateView](Sources/Views/Components/EmptyStateView.swift) |
| `#if os(...)` for true platform divergence only | `NoteEditorView` keyboard toolbar; `NotesRootView` watchOS routing; `WatchNotesListView` whole-file gated |

## How to run

1. Open Xcode → **File → New → Project → Multiplatform → App**.
2. Name it `NotesJournal`. Confirm iOS, macOS, and watchOS targets are added (Xcode's multiplatform template gives you iOS + macOS by default — add a watchOS app target manually via **File → New → Target → watchOS App**, sharing code with the multiplatform group).
3. **Set the deployment target to iOS 26 / iPadOS 26 / macOS 26 / watchOS 26** for each target. The agent assumes current OS APIs throughout (no `@available` checks).
4. Replace the generated files with the ones in [`Sources/`](Sources/). Add them to **all three** targets.
5. ⌘R for iOS, switch the scheme for Mac or Watch.

> Tip from the agent: don't run yet. Click into each preview canvas first — Light, Dark, and XXL should all read clearly before you ever hit ⌘R. The fastest design loop is the one without a build.

## Design choices the agent made (and why)

- **No custom font.** Default `Font.system(...)` gives Dynamic Type and SF Pro on every platform.
- **`Color(.background)` instead of `Color.white`.** Survives dark mode without an asset catalog entry.
- **`ContentUnavailableView` for empty + detail-placeholder.** The system pattern on every supported Apple platform — free dark mode + accessibility + look-and-feel parity with Apple's apps.
- **`NavigationSplitView` everywhere except watch.** Same code gives a single column on iPhone, two columns on iPad and Mac. No `if iPad` branching.
- **`Note` is a value type, edits flow through `@Binding`.** No `@Observable` class, no shared mutable state in the UI layer — the `MockNotesUseCase` actor owns the store.
- **`.background(.background)` on the editor scroll.** The `TextEditor` chrome would otherwise show its default gray on macOS.
- **Disney 12 → SwiftUI.** This sample stays animation-light on purpose; the bounce on row tap and the spring on selection are SwiftUI defaults. Add `.symbolEffect(.bounce)` to the compose icon on a successful save if you want the "appeal" principle in two lines.

## What's intentionally missing

- No persistence, no networking, no auth — `MockNotesUseCase` is the seam.
- No app icon (use Icon Composer; the agent recommends typography-only icons).
- No localization beyond what Apple's APIs give for free (date formatting, etc.).
- No tests — this is a UI sample, not a production starter.
